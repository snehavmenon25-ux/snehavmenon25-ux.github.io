1. Core TestComplete Concepts for Beginners

Unlike browser-only tools, TestComplete automates Windows desktop applications (.NET, WPF, WinForms, Delphi), web browsers, and mobile apps in a single IDE. Four building blocks form every reliable suite:

  • Project Suite & Project: A container holding your application configuration, object repository, test scripts, and execution logs.
  • TestedApps: Registers the executable path or browser URL so tests can launch, close, or restart the application cleanly before each run.
  • Object Browser & Name Mapping: Inspects live UI controls and maps long hierarchy paths into clean aliases (e.g., Aliases.OrdersApp.MainForm.SaveButton).
  • Keyword Tests vs. Script Units: Beginners often record a Keyword Test first, then convert or build modular routines in JavaScript or Python for loops, conditions, and reusable helper libraries.

2. Step-by-Step Project Setup

  1. Open TestComplete and select File → New → New Project.
  2. Name the project OrderEntryAutomation, choose Desktop (or Web), and select JavaScript or Python as your scripting language.
  3. Right-click TestedApps in the Project Explorer → Add → New Item, and browse to your application executable (for example, SmartBear's sample Orders.exe) or configure your target web browser URL.
  4. Open the Object Browser panel while your application is running to verify TestComplete recognizes internal control names (WinFormsObject, WPFObject, or web DOM elements).

3. Understanding Name Mapping & Aliases

Without Name Mapping, a raw object path looks brittle and hard to read:

Sys.Process("Orders").WinFormsObject("MainForm").WinFormsObject("ToolStrip1").WinFormsObject("NewOrderBtn")

With Name Mapping & Aliases, you map stable identification properties (such as WndClass, Name, or AutomationId) and collapse intermediate layout panels into a clean alias:

Aliases.Orders.MainForm.NewOrderBtn
  • Best Practice: Avoid mapping volatile properties like window coordinates (Left, Top) or dynamic window titles containing timestamps.
  • Wildcards: Use * in dynamic captions (e.g., Order #* - Details) so mapped objects remain valid across every test run.

4. Writing Modular Script Tests (JavaScript & Python)

Option A: JavaScript Script Unit (OrderTests.js)

Unit: OrderTests • Launch, Wait, Interact, Verify

Notice how WaitAliasChild prevents flaky timing errors when dialogs take a moment to open, and aqObject.CheckProperty logs structured pass/fail checkpoints.

// Launch application cleanly via TestedApps
function launchApp() {
  if (Sys.WaitProcess("Orders", 1000).Exists) {
    TestedApps.Orders.Close();
  }
  TestedApps.Orders.Run(1, true);
}

// Reusable helper function to create a customer order
function createCustomerOrder(customerName, productName, quantity) {
  let mainForm = Aliases.Orders.MainForm;
  mainForm.MainMenu.Click("Orders|New order...");

  // Wait up to 5 seconds for the modal dialog to appear
  let orderDlg = Aliases.Orders.WaitAliasChild("OrderForm", 5000);
  if (!orderDlg.Exists) {
    Log.Error("Order dialog did not open within 5 seconds.");
    return;
  }

  orderDlg.CustomerNameBox.SetText(customerName);
  orderDlg.ProductCombo.ClickItem(productName);
  orderDlg.QuantityBox.SetText(aqConvert.IntToStr(quantity));
  orderDlg.OKButton.ClickButton();
}

// Main test routine
function Test_CreateSingleOrder() {
  launchApp();
  createCustomerOrder("Sneha Menon", "FamilyAlbum", 3);

  // Verify the new row appears in the grid
  let ordersGrid = Aliases.Orders.MainForm.OrdersView;
  aqObject.CheckProperty(ordersGrid, "wItemCount", cmpEqual, 1);
  Log.Checkpoint("Order created and verified successfully.");
}

5. Data-Driven Testing with Excel or CSV (DDT)

Instead of duplicating test scripts for different inputs, use TestComplete's built-in DDT driver to loop through an Excel sheet or CSV file:

function Test_DataDrivenOrders() {
  launchApp();

  // Open an Excel worksheet or CSV file
  let driver = DDT.ExcelDriver("C:\\TestData\\OrdersData.xlsx", "Sheet1", true);

  while (!driver.EOF()) {
    let customer = driver.Value("CustomerName");
    let product  = driver.Value("Product");
    let qty      = driver.Value("Quantity");

    Log.AppendFolder("Testing order for: " + customer);
    createCustomerOrder(customer, product, qty);
    Log.PopLogFolder();

    driver.Next();
  }

  DDT.CloseDriver(driver.Name);
}

6. Beginner Troubleshooting Checklist

  • "Object Does Not Exist" error: Check if the window title or ID changed dynamically, or replace direct calls with WaitAliasChild("ControlName", 5000).
  • Script works locally but fails on CI agents: Ensure screen resolution and DPI scaling (100%) match across machines, and run via TestExecute with an active desktop session.
  • Keep scripts modular: Put login, navigation, and cleanup routines in a shared CommonUtils script unit and import them with //USEUNIT CommonUtils (JavaScript) or import common_utils (Python).
