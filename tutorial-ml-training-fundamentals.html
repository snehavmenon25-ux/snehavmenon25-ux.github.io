1. Dataset Splitting, Training & Testing

The Exam Analogy: Imagine studying for a certification exam. If the teacher gives you the exact 50 exam questions beforehand and you memorize the answers, getting 100% does not prove you understand the subject. To measure real learning, you need unseen questions on exam day.

  • Training Set (~70–80% of data): The practice textbook. The model looks at both inputs and correct answers repeatedly to adjust its internal parameters.
  • Validation Set (~10–15% of data): Mock practice exams taken during studying. Used to tune settings (like learning rate) and spot overfitting early without touching the final exam.
  • Testing Set (~10–15% of data): The final unseen exam held locked away until training finishes, giving an honest measurement of real-world performance.
from sklearn.model_selection import train_test_split

2. Loss Function: Measuring "How Wrong" the Model Is

Role: A Loss Function compares the model's prediction against the true answer and outputs a single penalty number (the loss). A high loss means a big mistake; a loss near zero means an accurate prediction.

  • Mean Squared Error (MSE) — For Numbers (Regression): Used when predicting continuous numbers like house prices or response latency in milliseconds. Example: If true latency is 200 ms and the model predicts 230 ms, squared error is (230 - 200)² = 900.
  • Binary Cross-Entropy (BCE) — For Yes/No Decisions: Used for two-class problems like "Is this test flaky? (Yes/No)" or "Spam vs. Not Spam". It heavily penalizes confident wrong guesses.
  • Cross-Entropy Loss — For Multiple Categories: Used when choosing one class among many (e.g., classifying a bug report as UI, Backend, Database, or Network).
import torch
import torch.nn as nn

# Example: Predicting whether a build will fail (1 = Fail, 0 = Pass)
loss_fn = nn.BCEWithLogitsLoss()

raw_prediction = torch.tensor([2.5])   # Model strongly predicts Fail (~92% probability)
actual_outcome = torch.tensor([1.0])   # Build actually failed

loss = loss_fn(raw_prediction, actual_outcome)
print("Loss penalty:", round(loss.item(), 4))  # Small penalty: 0.0789

3. Backpropagation: Finding Who Caused the Error

Role: A neural network contains thousands or millions of internal weights (knobs). Once the Loss Function tells us the total error, Backpropagation works backward from the output layer to the input layer (using the calculus chain rule) to calculate how much each individual weight contributed to that mistake.

Simple Analogy: If a relay race team finishes 5 seconds behind target time, backpropagation checks each runner's split to determine who slowed down and by how much—giving every weight a gradient (direction and steepness of error).

4. Optimizers: Turning the Knobs to Reduce Error

Role: Backpropagation only calculates the error gradients; the Optimizer is the algorithm that actually updates the model's weights to lower the loss on the next step.

  • Learning Rate (lr): Controls step size. Too large and the model overshoots the best answer; too small and training crawls slowly.
  • SGD (Stochastic Gradient Descent): Updates weights directly in the downhill direction of the gradient—simple and reliable.
  • Adam / AdamW (Most Popular Default): Automatically adapts the step size for each parameter using momentum and past gradient history, converging quickly on most tabular, vision, and NLP tasks.
# How Loss, Backpropagation, and Optimizer work together in 4 lines:
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)

optimizer.zero_grad()          # 1. Reset gradients from previous step

5. Overfitting vs. Underfitting (and How to Fix Both)

  • Underfitting (Too Simple): The model fails to learn basic patterns. Both Training Loss and Validation Loss stay high (like trying to fit a straight line through curved data). Fix: Train longer, add informative features, or use a slightly larger model.
  • Overfitting (Memorizing Noise): The model memorizes the training examples—including random quirks—so Training Accuracy reaches 99%, while Validation/Test Accuracy drops sharply on unseen data.

Four Practical Ways to Prevent Overfitting:

  1. Dropout (nn.Dropout(0.2)): Randomly turns off 20% of neurons during each training step so the network cannot rely on memorizing single pathways.
  2. Early Stopping: Monitor Validation Loss after every epoch and stop training automatically when validation error stops improving.
  3. Weight Decay (L2 Regularization): Penalizes overly large weights in AdamW(..., weight_decay=1e-2) to keep decision boundaries smooth.
  4. More Diverse Data / Data Augmentation: Add varied examples (or flip/crop images) so the model learns true concepts rather than surface details.
